**Source of truth:** [`DevelopmentDataSeeder.cs`](../backend/AngularApi/Services/DevelopmentDataSeeder.cs)

Passwords below are **placeholder values for non-production environments only**. Do not reuse them outside isolated test/staging systems.

## Overview

The seeder provisions reference data in this order:

1. Identity roles (`admin`, `doctor`, `user`)
2. Specializations and related services
3. Appointment statuses (`Active`, `Complete`, `Canceled`)
4. Default medical center (id `2`)
5. Admin, doctor, and patient user accounts
6. Doctor availability slots for each medical center with doctors
7. Five sample appointments spanning all statuses

Entity primary keys for users and appointments are generated by ASP.NET Identity and EF Core on first insert. Reference tables below list stable or predictable identifiers where the seeder assigns them explicitly.

## Idempotency Notes

Each seed step checks for existing data before inserting:

| Entity type | Idempotency guard |
|-------------|-------------------|
| Specializations | Skips entire step if any specialization exists |
| Appointment statuses | Inserts only missing enum values with explicit ids |
| Medical center | Returns existing id `2` or first center if present |
| Users (admin, doctors, patients) | Skips when email already registered |
| Doctor qualifications / affiliations | Created only with new doctor records |
| Doctor availability | Skips when slots exist for the medical center |
| Appointments | Skips when any appointment exists for the first seeded doctor |

Re-running the application or seeder does **not** duplicate users, centers, availability, or appointments. Interrupted startup resumes safely on the next run.
